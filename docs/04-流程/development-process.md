# 开发流程标准

> 本文件是每次开发的**第一份必读**。原则：小步走、每步验证、当日事当日记。

## 核心原则

1. **不要一口气做太多**：一次会话只推进 1 个阶段，阶段内再拆小步
2. **每步都有验证方式**：没有验证方式的步骤不算完成
3. **改动可回滚**：每个阶段开始时确认上一阶段成果可用
4. **当天收尾写日志**：完成事项 + 待办事项写入 `../devlogs/当天日期.md`

## 阶段划分（按序执行，每阶段验证通过再进下一阶段）

| 阶段 | 内容 | 验证方式 |
|---|---|---|
| 0 基础设施 | docs、devlogs、AGENTS.md、流程标准 | 文档齐全、索引可点（✅ 已完成） |
| 1 探明数据源 | 实测 opencode.db schema、字段、样例数据；确定增量依据 | 脚本输出 db 表结构 + 3 条样例记录；聚合结果与 `opencode stats` 抽查一致 |
| 2 数据层 | config.py / db_reader.py / aggregator.py / cache.py + 单测 | 单测全绿；CLI 冒烟：命令行直接跑聚合输出与 stats 一致 |
| 3 UI 骨架 | 小窗显示（先接假数据）：布局、毛玻璃、置顶、拖拽 | 启动可见、可拖、样式符合 ui-spec |
| 4 UI 交互 | 接真数据：粒度切换、◀▶、日历、右键菜单、自动刷新 | 手动操作逐项验证 + 截图 |
| 5 向导与设置 | 首启向导、设置窗、开机自启 | 首次运行流程走通；自启开关写注册表生效 |
| 6 打包交付 | PyInstaller 单 exe | 干净环境双击可运行；验收标准 S1~S6 |
| 7 收尾 | README、使用说明、清理 | 文档与实现一致 |

## 每日开发日志规范（`devlogs/YYYY-MM-DD.md`）

每次开发会话结束时自动追加，格式：

```markdown
# 2026-08-12 开发日志

## 今日完成
- [x] 事项（验证：xxx）

## 待办（明日/下次）
- [ ] 事项
```

- 会话开始时：先读 `devlogs/` 里最近一天的日志，接着待办做
- 会话结束时：写/更新当天日志
- 日志是唯一跨会话的进度凭证

## 验证纪律

- 涉及纯逻辑（聚合、口径、缓存）→ 先写/跑单测
- 涉及 UI → 启动程序手动验证 + 截图存 `devlogs/` 附件
- 涉及与 stats 对比 → 明确写"与 opencode stats 抽查一致"并附数字
- 不声明未验证的完成（verification-before-completion 原则）
